## Regole di lavoro
1. Distingui sempre: dichiarato dal documento / verificato (con output di comando) / ipotesi / pianificato. Il PDF non è lo stato reale finché non verificato.
2. Prima raccolta di fatti in sola lettura, poi contenimento, poi strutturali. Ordina per rischio reale e sfruttabilità.
3. Ogni modifica: precondizioni, comando, verifica, rollback, impatto atteso sul servizio. Una modifica per volta.
4. Prima di qualunque modifica: snapshot/backup OVH recente e `iptables-save` + `lxc config show` salvati fuori dal VPS.
5. Modifiche al firewall o a sshd da remoto: sempre con rete di sicurezza (rollback automatico temporizzato, es. `iptables-apply` o ripristino schedulato con `at`), e con una seconda sessione SSH aperta.
6. Se un'idea ha problemi tecnici, economici o di rischio, dillo. Alternative con vantaggi, svantaggi, failure mode e raccomandazione.
7. Cloudflare Free è un livello aggiuntivo, non sostituisce le correzioni. **Dal 25/10 gli NS di studiotecnicoverro.it sono su Cloudflare** (`chance`/`jessica`.ns.cloudflare.com; decisione ed esecuzione di Pietro, la delega è una condizione del piano Free; zona OVH Anycast mantenuta per il rollback, da verificare). **Stato letto via API il 25/10 (sola lettura):** zone `studiotecnicoverro.it` e `ingegneriaesicurezzasrl.it` active (Free), `intranet` e `intranetbeta` **proxied** verso 57.131.13.35 (in mattinata `intranet` era DNS only: riattivazione di Pietro, momento e motivo non registrati), SSL `full` (non strict), TLS minimo 1.0, Always Use HTTPS e HSTS off, AOP off, nessuna regola WAF custom né rate limit, Redirect Rule attiva. **L'origine NON è chiusa ai range Cloudflare: con il proxy attivo è la lacuna principale.** Sequenza dello strato Cloudflare (CF0-CF9 in `todo-findings-critici.md`): test funzionale in proxy (CF0) → SSL "Full (strict)" (CF1) → `real_ip` in nginx (CF2a) → origine chiusa ai soli range Cloudflare **in FORWARD** (IPv4 e IPv6; il DNAT passa da FORWARD, non INPUT) (CF2) → Authenticated Origin Pulls (CF3) → regole WAF gratuite (CF4). L'IP 57.131.13.35 è pubblico nell'SPF: il controllo efficace è il filtro firewall, non l'occultamento dell'IP. Nell'ipotesi AWS l'origine si chiude del tutto con Cloudflare Tunnel (`cloudflared` sulle istanze, nessun IP pubblico) oppure con un ALB (+circa 28 €/mese).

## Uso di Claude Code direttamente sul VPS
- Pietro ha autorizzato l'uso di Claude Code sul VPS.
- Fase 1 (sola lettura): nessuna scrittura, nessun riavvio di servizi. Solo comandi di ispezione (`ss`, `iptables-save`, `lxc list`, `docker ps`, `sshd -T`, `find`, lettura log).
